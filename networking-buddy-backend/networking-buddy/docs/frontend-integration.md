# Frontend integration contract — B and C

The backend preserves every URL and required request field in the plan.
It adds optional session IDs and response metadata. `/docs` and `/openapi.json`
are generated from the same models the backend actually validates.
Dates are ISO `YYYY-MM-DD`; IDs are opaque strings, not numeric counters.

## Endpoint ownership

| Owner | Method and path | Request body | Response |
| --- | --- | --- | --- |
| B | `GET /api/state` | None | `{user, contacts, tasks, game_sessions, games, today, mode}` |
| C | `POST /api/games/{game}/start` | None | `{reply, goal, title, game, max_turns, xp, rubric, session_id, source}` |
| C | `POST /api/games/{game}/turn` | `{history, session_id?}` | `{reply, turns_used, turns_remaining, game_complete, source}` |
| C | `POST /api/games/{game}/score` | `{history, session_id?}` | `{scores, best_moment, one_fix, rewrite_example, xp, xp_awarded, user, session_id, already_scored, source}` |
| C | `POST /api/tasks/{id}/complete` | `{met_name, role?, company?, hook, contact_id?}` | `{contact, task, xp, xp_awarded, user, already_completed}` |
| B | `POST /api/contacts` | `{name, how_met?, company?, role?, notes?}` | The saved contact object; HTTP 201 |
| B | `POST /api/coach/reminders` | None | `{reminders: [...], source}` |
| B | `POST /api/coach/draft` | `{contact_id, reason}` | `{draft, contact_id, source}` |
| Demo | `POST /api/reset` | None | Same shape as `/api/state` |
| Demo | `GET /api/health` | None | `{status: "ok", mode: "demo" or "live"}` |

Game IDs: `elevator_pitch`, `coffee_chat`, `follow_up`, `cold_call`.

`state.tasks` contains only open tasks. `state.game_sessions` contains the most
recent 20 completed games, newest first. `state.games` is the public catalog,
with title, goal, max_turns, xp, and rubric. `state.user` includes name, school,
major, target_roles, xp, streak, and last_active.

`source` is `demo`, `live`, or `fallback`. `mode` is the configured server mode,
even when a live request fell back. Reminders are deliberately generated by
their endpoint, not embedded in state. Load state and reminders together for
the home screen, and refresh both after scoring or a reflection.

## Shared fetch helper for B's app.js

This is a handoff example, not a file the backend installs in the frontend:

```javascript
async function api(path, {method = 'GET', body} = {}) {
  const response = await fetch(path, {
    method,
    headers: body === undefined ? {} : {'Content-Type': 'application/json'},
    body: body === undefined ? undefined : JSON.stringify(body),
  });
  const data = await response.json();
  if (!response.ok) {
    const message = Array.isArray(data.detail)
      ? data.detail.map(issue => issue.msg).join('; ')
      : data.detail || `Request failed (${response.status})`;
    const error = new Error(message);
    error.code = data.code;
    error.status = response.status;
    throw error;
  }
  return data;
}

const [state, coach] = await Promise.all([
  api('/api/state'),
  api('/api/coach/reminders', {method: 'POST'}),
]);
// Render state.user, state.tasks, state.games, and coach.reminders.
```

Use `textContent` when rendering names, notes, and model replies. Keep buttons
disabled while their request is running. On failure, keep typed input and
show the error so the student can retry.

## Games: C's game.js

The student is `user`; the persona is `assistant`. The start reply is the
first assistant message. Include it in history, followed by alternating user
and assistant messages. Do not include UI labels, system prompts, goals, or
score feedback in history.

```javascript
const game = 'coffee_chat';
const started = await api(`/api/games/${game}/start`, {method: 'POST'});
const sessionId = started.session_id;
const history = [{role: 'assistant', content: started.reply}];
let pendingTurn;

async function submitTurn(text) {
  // Build pendingTurn only once. If fetch fails, retry this same array.
  pendingTurn ??= [...history, {role: 'user', content: text.trim()}];
  const result = await api(`/api/games/${game}/turn`, {
    method: 'POST', body: {history: pendingTurn, session_id: sessionId},
  });
  history.splice(0, history.length, ...pendingTurn,
                 {role: 'assistant', content: result.reply});
  pendingTurn = undefined;
  // Display result.turns_remaining; if result.game_complete, show Finish.
  return result;
}

async function finishGame() {
  // Wait for any pending turn. Finishing is allowed after one student reply.
  const result = await api(`/api/games/${game}/score`, {
    method: 'POST', body: {history, session_id: sessionId},
  });
  // Render scores (1–5), best_moment, one_fix, rewrite_example.
  // Show result.xp as the session's reward.
  // Animate only result.xp_awarded; on a retry this is 0.
  // Apply result.user to the XP/streak display, then refresh home + coach.
  return result;
}
```

`max_turns` counts student messages, not total chat bubbles. Coffee chat allows
four; cold outreach allows three. The final persona reply is returned normally,
with `game_complete: true`. Finishing early is allowed after at least one student
message. Requests with no student messages or more than the maximum return 422.
Score history may end in either a student or persona reply.

For `elevator_pitch` and `follow_up`, start normally, append the student's
single answer, and call `/score` directly. Do not call `/turn` for these games.
The start `xp` is the available reward; starting or chatting earns nothing.

`session_id` is optional for compatibility with `{history}` clients. Always
send it in new code: the same session can score only once. A retry returns the
original feedback, `already_scored: true`, and `xp_awarded: 0`, with current
user totals. Start a new game to repeat practice. IDs survive server restart
and become invalid on reset. Active, unscored sessions are capped at 100.

History-only scoring deduplicates identical transcripts for the same game and
app date. This fallback prevents duplicate awards but cannot distinguish an
intentional second play; using sessions resolves that.

## Reflections: C's tasks.js

Present two main questions: “Who did you meet?” (name, role, company), and
“What is one specific thing to follow up on?” (`hook`). Name and hook are
required; role and company can be empty.

```javascript
const result = await api('/api/tasks/t1/complete', {
  method: 'POST',
  body: {
    met_name: 'Marcus', role: 'Data engineer', company: 'Qualtrics',
    hook: 'His team is moving to dbt',
  },
});
// result.contact is the new or updated contact.
// Animate result.xp_awarded and apply result.user.
// Refresh state and coach reminders to close the loop.
```

Contacts match by case-insensitive, whitespace-normalized name **and** company.
A match gets the hook appended to notes and last_contact set to today.
A different company creates a separate contact. If the user selects a known
contact, send its `contact_id` as well; its name must match `met_name`.
The seeded follow-up task `t3` already points to Daniel (`c2`); use its existing
contact for the reflection. Ambiguous identity returns 409 with code
`ambiguous_contact`, so the UI can ask for an explicit selection.

Repeating completion returns the original saved contact and reflection,
`already_completed: true`, and `xp_awarded: 0`. It does not create another
contact or overwrite the reflection. `xp` remains the task's nominal reward.

## Coach and contacts: B's home.js and contacts.js

Example reminder response:

```json
{
  "reminders": [{
    "contact_id": "c1",
    "headline": "Ask Sarah about the grant",
    "reason": "Sarah's September 30 grant deadline has passed. Ask how the submission went, and offer to discuss the outdated lab website they mentioned.",
    "suggested_action": "Ask how the grant submission went and whether help with the lab website would be useful.",
    "tip": "Your coffee chats score low on specificity. Ask about one concrete detail they mentioned."
  }],
  "source": "demo"
}
```

There may be zero to three reminders. Don't assume there are exactly three.
On tapping a card, send its ID and reason, then render the `draft` field:

```javascript
const drafted = await api('/api/coach/draft', {
  method: 'POST', body: {contact_id: card.contact_id, reason: card.reason},
});
// Show drafted.draft in a sheet, with a Copy button.
```

Drafting and copying a message do not earn XP or update last_contact. A completed
follow-up task records the real interaction and awards 100 XP in the seed.
The backend only drafts text; it does not send messages.

Add-contact `notes` must be an array of strings. Convert a textarea into a
single note or split it into nonempty lines:

```javascript
const saved = await api('/api/contacts', {
  method: 'POST',
  body: {name: 'Jamie', how_met: 'Career fair', company: 'Acme',
         role: 'Data engineer', notes: ['Discussed data quality tests']},
});
// saved is a Contact directly, not {contact: ...}.
```

Saved contacts contain `id`, `name`, `how_met`, `company`, `role`, `notes`, and
`last_contact`. Manual creation records a meeting today but gives no XP.
Disable repeated submissions; manual contact creation is not deduplicated.

## Errors and reset

| Status | Meaning |
| --- | --- |
| 201 | Contact created successfully |
| 404 | Unknown game, task, contact, session, or API URL |
| 409 | Invalid game state or ambiguous/mismatched contact |
| 422 | Missing/invalid field, history, or turn count |
| 503 | Storage unavailable; no successful reward commit |
| 403 | Reset disabled with `ALLOW_RESET=0` |

Failures return `{detail, code}`. `detail` is a string for business errors and
an array of `{loc, msg, type}` for schema validation. No secrets are returned.
Normal Claude failures keep the response usable with `source: "fallback"`.

Reset is **POST**, never GET. After reset, discard any local game session,
history, score screen, contact selection, and coach cards, then reload state
and reminders. Local cached IDs can otherwise point to discarded data.
